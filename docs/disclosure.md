### Design and Architecture:

#### Initial prompt:

We've previously talked about using the Muse headset for a project. The project we've decided on is: Using Muse with an android application to defer notifications until the user is no longer concentrating on a task. The basic idea is that the headset is reading the user's brain activity while they work, the app decides from that whether they're in a focused state or not, and while they are, incoming notifications get held back. Once the app decides they've come out of focus the held notifications get released all at once, or possibly in a short burst so the user isn't hit with twenty at a time. We have access to the Muse sdk, so getting the raw EEG and the band powers (alpha, beta, theta etc.) shouldn't be the hard part, the hard part is going to be deciding what "concentrating" looks like for a particular person and building the app around that.

I imagine the application would need some features in order to make it user specific and actually usable day to day:

The ability to turn on and off the notification deferral service. A simple toggle on the main screen, and probably a quick settings tile or a persistent notification with a pause button so the user doesn't have to open the app every time. It would also make sense for the service to turn itself off, or at least stop deferring, when the headset disconnects or is taken off, since at that point we have no data and shouldn't be holding anything back.

The ability to run in the background so the user could be busy with something on their phone and still have the notifications deferred. From what I understand this means a foreground service on android to keep the bluetooth connection to the Muse alive, plus a notification listener service to actually intercept the notifications. I'm not sure how the deferral itself should work, whether we can genuinely hold a notification and re-post it later, or whether we need to cancel it, store the content, and recreate it ourselves when the user is free. Either way the user should be able to see what has been held so far if they really want to, and there should be some kind of whitelist so calls, alarms and selected contacts or apps always get through regardless of focus state.

A feature that would make the thresholds user-specific. I was thinking of a brief benchmarking type activity where the user holds their finger on the screen, reads some text, releases when they are done and is instructed to 'relax' for a time period, then repeat this several times to gather enough information to create the user-specific thresholds. The finger on the screen is there so we have a clean label for which samples are "focused" and which are "relaxed" without the user having to do anything extra. Maybe five or six rounds of reading plus relaxing, so somewhere around five to ten minutes total. The reading material could be short passages of something fairly dense so they actually have to pay attention, and the relax phase could just be a blank screen with a countdown, or a breathing animation. Open to other ideas about how to do this. I've also wondered whether we need a third category, like a "distracted" or "idle phone use" state, where the user is scrolling but not actually working, since that's probably what the EEG looks like most of the time and I don't know how different it is from concentrating.

Thresholds should be saved, per user, and the user should be able to re-run the calibration whenever they want, since I'd expect things to drift with headset placement, time of day, caffeine, and so on. It might be worth storing the last few calibrations and either averaging them or letting the user pick which one to use. There should probably also be a manual fine-tune, like a sensitivity slider, so that if the app keeps thinking they're focused when they're not (or the other way round) they can nudge it without doing the whole calibration again.

There should probably be a time-out period so a brief lapse in concentration doesn't let the notifications through, this should be user-adjustable. Something like: the app only switches to "not focused" after the signal has been below the threshold for N seconds, with N defaulting to maybe thirty seconds or a minute and adjustable from a few seconds up to several minutes. It would allow for brief pauses in work without distractions, like looking out the window or reaching for a coffee. Similarly there probably needs to be a short delay before switching into the focused state, otherwise the first moments of sitting down would count as focus and start holding things straight away. I'm also wondering about a hard cap, so that nothing gets deferred for longer than, say, two hours no matter what the headset says, as a safety net against the app misreading someone and sitting on an important message all afternoon.

Beyond that I'd like some kind of log or history screen so the user can see when the app thought they were focused and how many notifications it held during each session. Partly for their own interest, partly so we can tell during development whether the thresholds are doing anything sensible. Signal quality from the Muse also needs handling somehow, if the electrodes aren't making good contact we should probably fall back to letting notifications through rather than guessing.

Things I'm less sure about: how much battery the constant bluetooth stream plus a foreground service is going to cost on the phone, and how long the Muse itself lasts in continuous use. Whether android's battery optimisation is going to kill the service after a while and how much the user will have to fiddle with settings to prevent that. Whether a single alpha/beta style ratio is actually going to separate focused from relaxed reliably enough for one person, or whether we'd need something more involved, and whether reading on a screen during calibration produces the same pattern as the actual work the user does (which might be typing, or talking, or working on paper, where eye and jaw movement artifacts are different). And whether the whole thing is annoying in practice, because being told your messages were held for you for forty minutes might feel worse than just getting them.
